# Allowlist do vocabulário legado — dívida declarada, não permissão
# =============================================================================================
# Formato: <caminho relativo ao repo>::<id-da-regra>::<identificador>::<contagem>
# `#` comenta a linha inteira; linha vazia separa bloco.
#
# Cada linha aqui é um nome que o repositório ainda diz errado e que a guarda
# `backend/tests/test_vocabulario.py` (ADR 0049) deixa passar **por ora**. A lista nasceu com o
# estado de `main` @ 80da2a5 — exatamente as ocorrências que a guarda encontrava naquele commit,
# nem uma a mais — e três testes a mantêm honesta:
#
#   * `test_nenhum_termo_banido_novo` reprova o que não está aqui — e também a ocorrência **a
#     mais** numa chave que já está;
#   * `test_a_allowlist_nao_guarda_linha_desnecessaria` reprova a entrada maior que a dívida que
#     ela isenta, forçando a baixa do número — ou a remoção da linha, quando a dívida zera;
#   * `test_a_allowlist_so_encolhe` guarda o teto (`TETO_DA_ALLOWLIST` = 30), que conta **dívidas
#     distintas** — linhas deste arquivo, não ocorrências no código. Os dois números não medem a
#     mesma coisa.
#
# A entrada **não carrega número de linha**, de propósito: dívida declarada não pode ser reaberta
# por alguém ter inserido um import acima dela. Ela carrega a **contagem**, que é a outra metade
# da mesma decisão: sem o número, `models.py::client-como-organizacao::client` isentaria as doze
# ocorrências de hoje **e a décima terceira** — e `models.py` é onde todo modelo novo nasce.
# Medido por sabotagem (ADR 0027): um `client = models.ForeignKey(...)` acrescentado ao fim de
# `models.py` passava em silêncio na primeira versão desta guarda.
#
# Pagar dívida em parte **abaixa o número da linha**; pagar inteira **remove a linha**. As duas
# coisas são cobradas, e a mensagem do teste diz qual número escrever.
#
# Quem paga cada bloco está em `docs/ontology/aliases.md`. Resumo, na forma que a ADR 0052 fixou:
# o nome da **classe** é a issue #67, o da **tabela** é a Fase 6, a **rota** e a **chave de
# payload** são a `/api/v2/`, e o split Evidence/Finding foi a Fase 3.

# O bloco tinha nove linhas e ficou com três. A fatia 2 (ADR 0052) renomeou a classe para
# `Account`, os dez campos que apontavam para ela para `account` e o `status` da conta para
# `lifecycle_status`: modelo, migração `0062`, serializers, viewset, `resource`, permissões,

#
# O que ficou, e por quê:
#
#   * `client` em `models.py`, **uma ocorrência**: `Project.client`. Ele é a projeção temporária
#     cuja fonte canônica é `engagement.account` (ADR 0050) e cuja remoção é a Fase 6. Renomeá-lo
#     criaria **duas** coisas com o nome canônico no mesmo objeto — `project.account` e
#     `project.engagement.account` — que podem divergir, e o nome canônico deixaria de identificar

#   * `clients` em `urls.py` — a **rota**, que morre na `/api/v2/`. `/api/v1/clients/` e o

#     porque o derivado da classe viraria `account`.
#   * `client_consent` — consentimento da organização, no `Case`. Vira `account_consent` quando a
#     Fase 6 fizer o renome físico; não entra agora porque é chave de payload da `/api/v1/`.

# `gate_outcome` — a chave de payload, e só ela. Morre na `/api/v2/`.
# O bloco tinha onze linhas e ficou com uma. A decisão D7 renomeou `GateOutcome` para
# `GateDecision`, e a ADR 0052 antecipou o renome de classe e de campo para a issue #67 em vez de
# esperar a Fase 6: modelo, migração, `journey.py`, views, portal, tipo TS e tela já dizem
# `gate_decision`. O que ficou é o alias de leitura do `ProjectPhaseSerializer` e do
# `PhaseEventSerializer` — a mesma chave saindo com o mesmo valor, porque um consumidor da
# `/api/v1/` não tem como saber que o nome mudou. Rota e chave de payload morrem na `/api/v2/`,
# que é o prazo que a `aliases.md` sempre deu a elas.
#
# Esta continua sendo a única regra que casa **referência** e não declaração, porque o
# identificador inteiro está errado: não existe uso legítimo do nome antigo *dentro* do código.
# A exceção é a chave de payload, e ela está declarada aqui — com a regressão que impede removê-la
# antes da hora (`backend/tests/regression/test_o_alias_do_gate_sobrevive_na_v1.py`).
#
# Segunda linha, issue #67 (fechamento) — `openapi_aliases.py` precisa do mesmo nome literal.
# O critério de aceite "versionar a depreciação do alias no próprio contrato" criou
# `ALIASES_DEPRECIADOS` (`backend/apps/core/openapi_aliases.py`), o mapa que o
# `POSTPROCESSING_HOOKS` do drf-spectacular usa para marcar `deprecated: true` em cada alias no
# `openapi.yaml`. Para `ProjectPhase`/`PhaseEvent` esse mapa **precisa** conter a string
# `gate_outcome` — é o nome da propriedade que o esquema expõe, e o hook a procura por igualdade
# de texto. Não há como expressar isso sem a referência: é a mesma exceção de cima, num arquivo
# novo. A referência foi reduzida a **uma** ocorrência (uma constante, reaproveitada nas duas
# entradas do mapa) antes de entrar aqui — ver o comentário no próprio módulo.
#
# **As duas linhas deste bloco morrem juntas, e na mesma hora.** O mapa de depreciação existe para
# anunciar o alias; quando a `/api/v2/` parar de emitir `gate_outcome`, não há mais o que anunciar
# — a entrada sai de `ALIASES_DEPRECIADOS` e a referência sai com ela. Este bloco é o único da
# allowlist cujo prazo é o mesmo para as duas linhas.
# ---------------------------------------------------------------------------------------------
